# Работа над проектом

Для первого запуска начните с [README](README.md). Требования заказчика и
результаты проверки собраны в [брифе](docs/product/BRIEF.md) и
[отчёте о выпуске](docs/quality/RELEASE_2026_11_27.md).

## Запуск и проверка

- [Локальный запуск на Windows](docs/operations/LOCAL_SETUP.md)
- [Запуск через Docker Compose](infra/docker/README.md)
- [Проверки API и прогон с локальной моделью](evals/README.md)

Перед публикацией изменений проверьте backend через pytest, а интерфейс
через `npm run build` из каталога `frontend`. Если изменение касается
поиска или модели, прогоните соответствующий сценарий на том же корпусе
и зафиксируйте профиль рантайма. Проверки с тестовым адаптером, живой
генерацией и embeddings указывайте отдельно.

## Документы и ответы

- Храните документы, версии, разрешения, исходные блоки и историю в SQLite.
  Chroma используется как перестраиваемый индекс. Для нового профиля
  embeddings соберите и проверьте отдельную генерацию индекса.
- Определяйте применимость редакции по подтверждённым реквизитам,
  периоду и области действия. Сохраняйте неизвестные факты и проверяйте
  приоритет источников для конкретного процесса.
- Проверяйте права перед поиском и перед выдачей ответа. Контекст от
  клиента сужает поиск. Роль и группы определяются сервером.
  Фрагменты документов обрабатываются как данные.
- Сохраняйте исходный текст и его координаты до разбиения на фрагменты.
  В цитате указывайте редакцию, блок, фрагмент и точный локатор. Для DOCX
  используйте абзац, таблицу или пункт.
- Проверяйте структуру ответа, доступность ссылок и поддержку каждого
  вывода исходным текстом. При расхождении
  положений покажите основания обеих сторон. При неполных сведениях
  предложите уточнение или отправьте вопрос на разбор.
- Импорт и публикация редакций выполняются оператором. Агент поиска
  читает только разрешённые источники. Пример применения привязывайте
  к существующей цитате и показывайте как практику после проверки.
- Ключи, рабочий корпус, вопросы, ответы и индексы храните в закрытом
  контуре. Обычные журналы ограничивайте служебными метаданными.
  Используйте `.env` для настроек сеанса и `runtime/` для локальных данных.

Код и API ведём на английском, документацию на русском. Версии зависимостей,
образы и хеши весов фиксируем в репозитории. Текущая схема использует
один backend и ограниченный цикл обработки вопроса. Решения о разбиении
сервиса принимаем по результатам измерений.

История подготовки и архив прежнего эксперимента описаны в
[аудите](docs/preparation/AUDIT.md).
