## Продуктовый сценарий

На экране ответа — краткий вывод, подтверждённые пункты и ссылки вида [1], [2].
Панель источника показывает название, редакцию, период действия и точную выдержку.
Для PDF — физическая страница и при наличии печатная метка; для DOCX — раздел,
абзац или строка таблицы. Не придумывать номера страниц DOCX.

У цитаты можно открыть форму «Рассказать, как применили пункт». Ввод состоит
из ситуации и действия. После сохранения показывается статус «На проверке».
Оценка «полезно» оценивает ответ отдельно. Если появится выдача одобренных
заметок, показывать их как примеры практики в отдельном блоке.

Запрос на уточнение — отдельное состояние с понятным вопросом, например
«Для какого юридического лица и на какую дату?». Конфликт документов
показывает оба основания и недостающий способ разрешения, а не случайного победителя.

Экран документов для администратора: upload → разбор → индексирование →
готовность. Публикация редакции и исправление метаданных доступны только
разрешённому администратору. Процент готовности не изображать без измеримого прогресса.

## Технические границы

- UI обращается только к backend; ключи модели и Chroma не попадают в браузер.
- Типы API генерируются/сверяются с OpenAPI после появления backend-контрактов.
- VITE_API_BASE_URL — публичный URL, никакие секреты через VITE_ не передаются.
- Текст ответа отображается с безопасной обработкой Markdown/HTML.
- Server ID и статусы являются источником истины; refresh не запускает
  повторно загрузку/индексацию/вопрос без отдельного действия.
- Начать с polling заданий; streaming/SSE добавлять после рабочего полного пути.
- В спринте создать шаблон react-ts с проверенной версией Vite, зафиксировать
  package-lock.json, добавить typecheck, build и несколько сценариев UI.
