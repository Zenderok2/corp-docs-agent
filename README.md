# Агент ответов по корпоративным документам

Конкурсный прототип команды Brainstorm для кейса Софтлайн на хакатоне «ИИкузница».

[Открыть стенд](https://d5d4n1iop8aguhgmqkkj.p8361f8z.apigw.yandexcloud.net/) ·
[Макет интерфейса](docs/product/INTERFACE.md) ·
[Калькулятор стоимости запроса](https://raw.githubusercontent.com/Zenderok2/corp-docs-agent/6384ebd888d219b2da7ecd220c475986a11fff97/submission/economics.xlsx)

Сотрудник задаёт вопрос о рабочем процессе, получает краткие тезисы со ссылками
на точные выдержки и при необходимости уточняет контекст. Если в регламентах есть
пробел, запрос поступает в службу качества. Её опубликованный ответ можно
применить при повторном обращении с тем же контекстом и теми же основаниями.
При расхождении регламентов агент показывает оба положения и передаёт
вопрос на проверку. Публикация консультации приостанавливается до нового
разбора по действующим документам.

## Доступ к стенду

В гостевом режиме доступны шесть вымышленных документов и готовые примеры
вопросов. Выберите «Согласование плана проекта» и нажмите «Спросить».
После уточнения подразделения откройте цитату в панели «Источники».

| Кнопка | Что ввести | Что откроется |
| --- | --- | --- |
| **Войти** | Код участника, который выдаёт команда | Четыре регламента конкурсной задачи |
| **Служба качества** | Отдельный код проверяющего, который выдаёт команда | Входящие обращения и проверка примеров применения. Из этого раздела можно опубликовать или отозвать консультацию |

Обе формы принимают только код доступа. В сеансе проверяющего кнопка
«Служба качества» открывает очередь обращений.
[Готовность и версия стенда](https://d5d4n1iop8aguhgmqkkj.p8361f8z.apigw.yandexcloud.net/health/ready).

## Сценарии

- **Ответ по документам.** Агент извлекает основания из нескольких источников.
  У каждой цитаты есть редакция, точный локатор и хеш исходного файла.
- **Уточнение.** Если ответ зависит от юрлица, подразделения, продукта или типа
  лицензии, агент задаёт уточняющий вопрос. Для комплексного проекта он показывает
  применимые пункты по каждому выбранному подразделению.
- **База знаний.** Агент отправляет вопрос службе качества через встроенную
  тестовую почту и оставляет копию сотруднику. Проверяющий отвечает в цепочке,
  а подтверждённый ответ появляется в базе знаний с пометкой «Служба качества».
  Письма можно скачать в формате `.eml`.
- **Практика.** Сотрудник отправляет пример по выбранному пункту. Одобренный
  пример показывается отдельно рядом с этим пунктом.

В репозитории шесть вымышленных файлов из `data/samples`. Они позволяют
воспроизвести сценарии без документов заказчика. Рабочий корпус импортируется
оператором. Его исходники, индексы, данные сессий и ключи хранятся в контуре команды.

## Запуск

Для Docker Compose нужен работающий Engine и доступ к реестрам при первой
сборке. Скрипт загружает закреплённые файлы моделей и проверяет SHA-256.

```bash
bash infra/docker/fetch-models.sh
docker compose build api web
docker compose run --rm --no-deps operator
docker compose up -d
```

Интерфейс доступен на `http://localhost:8080`. Для локальной копии задайте
в `.env` `STAFF_ACCESS_CODE` для участника и `QUALITY_ACCESS_CODE` для
проверяющего. После изменения кодов перезапустите API. Гибридный режим,
параметры внешнего стенда и импорт своего корпуса описаны в документации.
[Docker Compose](infra/docker/README.md) · [Запуск на Windows](backend/README.md).

## Устройство

| Слой | Компоненты |
| --- | --- |
| Интерфейс | React, TypeScript, Vite |
| Очередь и API | FastAPI, Python 3.12, сохраняемые задания SQLite |
| Импорт | PyMuPDF для PDF, python-docx для DOCX; также UTF-8 TXT и Markdown |
| Поиск | FTS5 с русской морфологией и глоссарием, связи документов, соседние пункты и дополнительный индекс ChromaDB |
| Модели | Раздельные серверы llama.cpp для chat и embeddings |

SQLite хранит документы, текстовые блоки, историю, разрешения и практику.
Изменение набора или профиля embeddings запускает сборку отдельной генерации
индекса. Переключение происходит после проверки размерности, количества
записей и ревизии корпуса. Решение о доступе к источникам принимает backend.

| Документ | Содержание |
| --- | --- |
| [Бриф](docs/product/BRIEF.md) | Обязательные сценарии и вводные заказчика |
| [Реализованный API](docs/architecture/API.md) | Вопросы, цитаты, роли, публикации и практика |
| [Контрольные проверки](evals/README.md) | Проверки без модели и прогон с локальными провайдерами |
| [Регламент](docs/preparation/HACKATHON.md) | Сроки и материалы сдачи |
| [Экономика](docs/operations/ECONOMICS.md) | Методика расчёта одного запроса |

Подготовительный шаблон зафиксирован отдельным коммитом. Ранее разработанный
агент поддержки сохранён локально в `archive/support-agent`. Его код и данные
в новом агенте не используются.
