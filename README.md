# Агент ответов по корпоративным документам

Кейс хакатона «ИИкузница», трек **«Корпоративные процессы»**.
Сотрудник получает ответ по регламентам и лицензированию с проверяемыми
цитатами, затем при желании оставляет пример применения выбранного пункта.
Запись сохраняется для проверки командой качества.

**Этап на 25 ноября 2026 — подготовка к спринту.** Организаторы подтвердили
небольшой файловый корпус регламентов и материалов о продуктах и лицензировании.
ТЗ, корпус и примеры вопросов выдадут на старте 26 ноября. Отдельного набора
ответов заказчик не предоставит. Приложение пока на стадии проектирования.

[Репозиторий команды на GitHub](https://github.com/Zenderok2/corp-docs-agent)
создан пустым и приватным для подготовки. Для сдачи потребуются публичный
репозиторий, URL стенда и отдельная ссылка на расчёт стоимости запроса.
[Действующие правила](docs/preparation/HACKATHON.md#комплект-сдачи-по-п-45).

На старте откройте [шаблон первого часа и вопросы к брифингу](docs/preparation/KICKOFF.md).
Для переезда на компьютер демонстрации откройте [инструкцию переноса на другой ПК](docs/operations/TRANSFER.md).
Подтверждённые вводные и расхождения в ответах собраны в
[разборе FAQ](docs/preparation/ORGANIZER_QA.md).

## Стек

| Слой | Решение |
| --- | --- |
| Интерфейс | React + Vite + TypeScript |
| API и агентский процесс | Python 3.12 + FastAPI + Pydantic |
| Метаданные, задания, версии, история | SQLite |
| Поиск по точным словам | SQLite FTS5 |
| Семантический поиск | Локальные embeddings и ChromaDB, после базового прохода на FTS5 |
| Разбор файлов | PyMuPDF для PDF, python-docx для DOCX |
| Генерация | Локальный llama.cpp, совместимый HTTP API, Qwen как кандидат |
| Embeddings | Отдельный локальный профиль для документов и запросов |
| Развёртывание | Нативный запуск на Windows для первого прогона, Docker Compose для упаковки |

FTS5 дополняет векторный поиск для номеров приказов, аббревиатур и точных
названий. SQLite хранит оригинальные фрагменты и состояние; Chroma —
перестраиваемый индекс. Парсинг, поиск, генерация и векторизация спроектированы
для работы внутри контура команды.

## Структура папки

```text
backend/
  src/corp_docs_agent/
    api/                # HTTP API, права, входные и выходные схемы
    core/               # настройки, lifecycle, общие ограничения
    domain/             # документы, версии, ссылки, ответы, политики
    ingestion/          # PDF/DOCX, блоки, чанки, задания индексации
    retrieval/          # FTS5 + Chroma, объединение и фильтрация
    agent/              # поиск, уточнение, проверка доказательств, ответ
    providers/          # chat, embeddings, хранилище векторов
    persistence/        # SQLite, миграции, репозитории
  tests/                # будущие unit/integration-проверки
frontend/
  src/
    app/                # оболочка, маршруты, провайдеры
    features/
      ask/              # вопрос, ответ, уточнение, обратная связь
      documents/        # загрузка, метаданные, версии, индексация
      sources/          # цитаты и просмотр источника
    shared/             # типизированный API-клиент и общие компоненты
infra/docker/           # проект сервисов, томов и сетевого доступа
data/
  inbox/                # локальные входные файлы, содержимое не в Git
  samples/              # место для разрешённых синтетических примеров
evals/                  # план контрольных вопросов и метрик
docs/                   # требования, архитектура, контракты и план реализации
archive/support-agent/  # прежний кейс целиком, с проверенными хешами
```

Каталоги уже созданы. README и `.gitkeep` задают их назначение; исполняемые
модули, package.json, Dockerfile и compose.yaml ещё предстоит создать в спринте.
Команды `npm run dev` и `docker compose up` сейчас не запускают новое приложение.

## Целевой сценарий

1. Оператор импортирует предоставленные файлы с реквизитами редакции и области действия.
2. Импорт извлекает текст с координатами источника и строит локальный индекс.
3. Агент собирает основания из нескольких документов и при необходимости получает
   соседние пункты, приложенные правила или сведения о делегировании.
4. Система проверяет цитаты. Ответ ссылается на страницу PDF или пункт/абзац DOCX.
5. При нехватке сведений, конфликте редакций или неизвестном контексте
   агент сообщает об ограничении и задаёт уточняющий вопрос.
6. Сотрудник привязывает пример применения к пункту. Команда качества
   получает запись для проверки.

Это целевое поведение, а не отчёт о реализованных функциях. Автоматическое
подписание, изменение регламентов и отправка писем в MVP не входят.
