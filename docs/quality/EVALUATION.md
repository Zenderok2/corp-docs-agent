# Приёмка поиска и ответов

Это спецификация сценариев, не готовые автотесты и не результаты измерений.
Корпус и контрольные ответы ещё не предоставлены.

## Подготовка набора

Организаторы выдадут примеры вопросов без отдельного комплекта эталонов.
Разметить собственный компактный набор по материалам двух наборов.
Начать с 6–10 вопросов, включая 2 составных, 2 по лицензированию, конфликт,
нехватку сведений и поиск по реквизитам. По возможности расширить до 15–30.
Синтетический набор разметить отдельно.
Версии документов, дата вопроса и права тестового пользователя фиксируются.
Настроечную и контрольную выборки не смешивать.

Для каждого QA-ID: вопрос, контекст/дата/principal, допустимые версии,
ожидаемые утверждения и цитаты, запрещённые выводы, ожидаемый outcome.
Scripted provider проверяет процесс и ошибки; качество реальной генерации
и embeddings требует отдельного live-прогона.

## Сценарии

| ID | Ситуация | Критерий приёмки |
| --- | --- | --- |
| QA-01 | Кто подписывает агентский договор | Названы роль/условия, только если подтверждены применимыми документами; ссылки на конкретные пункты |
| QA-02 | Какой регламент действует сегодня | Правильная подтверждённая редакция, не последний загруженный файл |
| QA-03 | Кто отвечает за этап | Корректно извлечена роль из таблицы/текста, сохранён контекст столбцов и условий |
| QA-04 | Точный номер приказа/аббревиатура | Точное совпадение не потеряно семантическим перефразированием |
| QA-05 | Перефразированный вопрос без точных терминов | Находится правильный пункт через смысловой поиск |
| QA-06 | Прямого ответа нет | not_found с объяснением пробела; нет ответа из общих знаний модели |
| QA-07 | Не указаны юрлицо/сумма/дата, от которых зависит подписант | needs_clarification, один конкретный вопрос; без случайного выбора |
| QA-08 | Доказана только часть вопроса | partial; подтверждённое отделено от неизвестного |
| QA-09 | Два источника противоречат друг другу | conflict с обоими основаниями; без выбора по similarity score |
| QA-10 | Историческая дата | Использована редакция, действовавшая в тот момент; дата явно отражена |
| QA-11 | Черновик новее действующего | Черновик не заменяет подтверждённый регламент |
| QA-12 | Приказ изменяет только один пункт | Остальной документ не отменён автоматически; область изменения учтена |
| QA-13 | Новый документ действует в другом юрлице/подразделении | Не подменяет применимый источник |
| QA-14 | PDF с разными физическим номером и печатной меткой | Источник открывает нужную физическую страницу; подпись однозначна |
| QA-15 | DOCX с таблицами/соседними абзацами | Сохранён порядок; citation указывает правильную ячейку/абзац, не придуманную страницу |
| QA-16 | Сканы/защищённый/повреждённый файл/неподдержанный формат | needs_ocr/понятная ошибка; не ready с пустым текстом |
| QA-17 | Повторная загрузка/повтор index-job/двойное нажатие | Идемпотентность без дублирования; разные правки метаданных не сливаются случайно |
| QA-18 | Сбой между записью SQLite и Chroma | Неполная генерация не активируется; прежний поиск остаётся согласованным |
| QA-19 | Смена embedding profile/размерности | Новый индекс; нет смешивания векторов; query/doc пара проверена |
| QA-20 | Документ удалён/права отозваны, старый vector ID ещё существует | Фрагмент не попадает в контекст, ответ, citation или сохранённую историю |
| QA-21 | Клиент подставил user_id/groups/filter другого отдела | Scope не расширен; недоступные названия/счётчики не раскрыты |
| QA-22 | Prompt injection в файле/вопросе | Нет расширения инструментов, чтения чужого корпуса, вызова URL/команд |
| QA-23 | LLM придумала citation ID/quote/роль/дату | Невалидная структура/цитата отклонена; неподдержанный вывод не утверждается |
| QA-24 | Citation ID существует, но пункт не подтверждает вывод | Проверка поддержки/ручная оценка выявляет ошибку; ID не считается доказательством |
| QA-25 | Повторяющийся поиск, timeout, 429, неверный ключ | Ограниченный цикл и понятная техническая ошибка; не not_found и не ложный успех |
| QA-26 | Рестарт на разборе/индексации/ответе | Задание не теряется молча; повтор не дублирует активную генерацию |
| QA-27 | Новый вопрос/смена источника/refresh UI | Связаны правильные question/answer/source IDs, нет старого ответа от другого вопроса |
| QA-28 | Провайдер embeddings недоступен | Явная ошибка или обозначенный lexical-only режим; нет молчаливой подмены модели |
| QA-29 | Выгрузка оригинала/длинный архив DOCX/имя с ../ | Проверены права/лимиты; нет обхода storage, распаковки без лимита и исполнения вложений |
| QA-30 | Ошибка или лог содержит ключ/сырой документ | В обычной диагностике только безопасные поля и request_id |
| QA-31 | Ответ требует два правила из разных документов или разделов корпуса | Для каждого вывода есть своё основание. Без одного из источников ответ становится частичным или просит уточнение |
| QA-32 | Ответ и повторный поиск при отключённом внешнем доступе | Парсинг, индекс, chat и embeddings выбранного режима работают в контуре команды |
| QA-33 | Условия продуктовой лицензии зависят от редакции и сценария использования | Ответ сохраняет условия и исключения, ссылается на применимую версию правил |
| QA-34 | Сотрудник сохранил пример применения выбранного пункта | В очереди видны ситуация, действие и исходная редакция. Повтор отправки и перезапуск не дублируют запись |
| QA-35 | Заметка противоречит официальному правилу или ссылается на чужую цитату | Чужую цитату нельзя использовать. Непроверенная заметка не появляется в ответах. При показе одобренных заметок видно, что это практика |
| QA-36 | Жюри открывает конкурсный URL с другого устройства и задаёт вопрос | Доступен полный сценарий на сданной версии. Chat, embeddings и индекс не требуют внешних API |
| QA-37 | Стоимость запроса рассчитана по замерам выбранной версии | Число вызовов, токены, объём и затраты на инфраструктуру воспроизводимы. Формула и открываемая ссылка на шаблон проверены |
| QA-38 | Срок согласования различается по подразделениям | При неизвестном подразделении есть уточнение и варианты со ссылками. Для комплексного проекта сроки и условия сгруппированы по областям |
| QA-39 | Сотрудник назвал РП «проджект-менеджером» | По глоссарию находится пункт с официальным названием роли |
| QA-40 | Краткий ответ поменял срок, единицу или пропустил условие | Неподтверждённый тезис убран, исходная выдержка доступна. У показанного тезиса есть свои ссылки |
| QA-41 | Служба качества ответила и позднее уточнила ответ | Сотрудник получил копию и письма с привязкой к цепочке. Повторный вопрос использует последнее опубликованное правило службы качества |
| QA-42 | Сотрудник спросил текущий валютный курс | Пояснена область применения агента. Служба качества не получает лишнее письмо |
| QA-43 | По одному вопросу обнаружены расходящиеся пункты и есть старая консультация | Агент ссылается на оба пункта, передаёт вопрос на проверку. В карточке видно, почему публикация приостановлена |
| QA-44 | Черновик консультации меняет число в процитированном сроке, затем проверяющий исправляет его | API возвращает замечание по сроку. Согласующееся дополнение доступно при совпадающих основаниях. После смены корпуса история сохраняется, а повторное использование требует нового разбора |

## Измерения

| Метрика | Способ оценки |
| --- | --- |
| Retrieval recall@k | Попал ли эталонный подтверждающий фрагмент в кандидаты/контекст; отдельно lexical, vector, hybrid |
| Корректность ответа | Проверка утверждений владельцем процесса, с условиями/датой/областью |
| Citation precision | Поддерживает ли процитированный фрагмент связанное утверждение |
| Citation coverage | Все ли проверяемые утверждения имеют необходимые основания |
| Корректное воздержание | not_found/clarification/conflict на нужных отрицательных случаях |
| Актуальность | Правильная редакция и дата на temporal-кейсах |
| Доступ | Нет недоступного текста в контексте/ответах/истории на тестовом наборе |
| Задержка | p50/p95 отдельно для индексации, поиска, генерации и общего ответа |
| Практика | Доля заметок с валидным пунктом, число записей на проверке и проверенных записей в пилоте |
| Стоимость | Индексацию замерять отдельно. Для ответа учесть query embeddings, LLM, повторы и долю инфраструктуры. [Калькулятор](../operations/ECONOMICS.md) |

Стартовые цели проекта: все проверки доступа/версий/идемпотентности пройдены,
нет неподтверждённых утверждений на базовых приёмочных примерах, ответ укладывается
в проектный дедлайн 45 секунд. Эти цели не согласованы с заказчиком и ещё не достигнуты.
Процент «уверенности модели» и расстояние Chroma не заменяют метрики выше.

При live-прогоне сохранять corpus/index/profile/model/prompt version, режим,
дату, usage, число повторов и результаты по QA-ID. Маленький демонстрационный
набор не доказывает промышленную точность или 40%-ное улучшение.

Экономический baseline — показатели из описания задачи, пока не измеренные нами.
Пилот сравнивает одинаковые вопросы до/после, учитывает проверку ответа сотрудником,
долю повторных поисков, стоимость обработки корпуса и ручного сопровождения.
