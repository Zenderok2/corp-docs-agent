# Чек-лист кик-оффа

Открытие 26 ноября в 10:00 МСК, сразу после него кик-офф. Заполнить по ТЗ и материалам.
Текущее понимание кейса отражено в [брифе](../product/BRIEF.md).

## Что уточнить заранее, если есть возможность

1. **Режим доступа жюри к стенду.** Может ли жюри войти по демо-учётке или
   другому согласованному способу? Какие файлы, названия и выдержки можно
   открывать по URL? Требование о стенде подтверждено. [Правила сдачи](HACKATHON.md).
2. **Доступная машина команды.** Где реально будет работать модель вместе с
   браузером и записью экрана? На текущем ПК мало свободной RAM. Выбор машины
   и модели определяют замер и качество, а не закреплённый организатором список.
   Для нового ПК есть [инструкция запуска на Windows](../operations/LOCAL_SETUP.md).
   Проверить, на каком хосте будет работать стенд между сдачей и питчем.

## Что закрыть на кик-оффе

| Вопрос | Что зафиксировать | Решение по умолчанию, если в ТЗ нет ответа |
| --- | --- | --- |
| Какие файлы в обоих наборах? | Форматы, число файлов и страниц, сканы, таблицы, структура папок | Поддержать форматы фактической поставки. Для сканов отдельно оценить объём OCR |
| Какие признаки актуальности есть? | Дата вступления, редакция, отмена, область, исключения и ссылки на приложения | Учитывать только признаки из материалов. При конфликте дать ссылки и причину, запросить контекст |
| Что обязательно показать? | Типы вопросов по лицензированию и регламентам, требуемый формат ответа, одна задача с несколькими документами | Короткий ответ, точные цитаты, объяснение условий. Собственные эталоны по примеру каждого типа |
| Кто проверяет примеры применения? | Какие поля собирать, кто видит заметки и может ли агент показывать одобренные записи | Ситуация и действие по выбранной цитате. Хранение со статусом «На проверке», очередь для команды качества |

Повторно спрашивать про API заказчика, отдельный тестовый набор, доступ к GPU
или обязательность SSO смысла нет. Эти темы разобраны в [FAQ](ORGANIZER_QA.md).

## Порядок сборки

1. Импорт непосредственно из файлов, локальный FTS5, сохранение координат.
2. Ответ по нескольким документам с проверкой цитат, конфликтами и уточнением.
3. Веб-экран вопроса и источников. Форма заметки по цитате и очередь проверки.
4. Развернуть рабочую версию на стенде. Проверить URL извне и замерить стоимость.
5. Сравнить FTS5 с локальными embeddings и Chroma, если основные проверки пройдены.
6. Зафиксировать сданную версию и записать демонстрацию на материалах задачи.

Подробный [план спринта](SPRINT_PLAN.md). Для разметки использовать
[карточку контрольного вопроса](../../evals/README.md).

## Перед сдачей

- [ ] Ссылка на видео до 3 минут одним фрагментом на материалах задачи.
- [ ] Описание в форме кабинета с функциями, ограничениями, запуском, моделями
  и раскрытыми наработками.
- [ ] HTTPS-ссылка на публичный репозиторий с историей. Проверить файлы и
  историю перед открытием доступа. Исключить документы, индексы, веса, заметки и секреты.
  Публиковать только конкурсную ветку. Сохранить публичный доступ до объявления результатов.
- [ ] URL рабочего стенда. Полный сценарий проверен извне. Стенд и последний
  коммит до дедлайна соответствуют друг другу, SHA сохранён для проверки.
- [ ] [Расчёт стоимости запроса](../operations/ECONOMICS.md) по замерам.
  Ссылка даёт скачать заполненный файл без авторизации.
- [ ] Отправить до **28 ноября, 10:00 МСК**. Оставить резерв до дедлайна.
- [ ] Вход жюри на питче отрепетирован. По присланному FAQ держать стенд до
  **3 декабря, 23:59 МСК** и быть готовым восстановить его по запросу до результатов.
