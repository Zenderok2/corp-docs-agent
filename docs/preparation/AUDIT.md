и входных файлов из Git и хеши 40 файлов архива.
Таблица и выводы ниже относятся к состоянию проекта **15 ноября**.

Дата: 15 ноября 2026. Активная задача — корпоративные документы, не клиентская поддержка.

## Изменения

Прежние `app/`, `ui/`, `data/`, `docs/`, README, requirements и .env.example
перенесены в archive/support-agent. Для всех **40 файлов** (без сгенерированных
pycache) до переноса записаны исходный путь, архивный путь и SHA-256; после
переноса хеши сверены. Удаления исходного содержимого не выполнялись.
В архив также вошли инструкции прежнего проекта.

В локальном архиве находятся манифест `MANIFEST.json` и исходный отчёт
`docs/preparation/BASELINE.md`.
Хеши подтверждают содержимое, а не дату происхождения или конкурсную допустимость.

README, памятка разработчика, бриф, архитектура, API, среда и приёмка переписаны под
новый кейс. Добавлены каталоги backend, frontend, infra, data и evals с
описаниями/`.gitkeep`. Секреты/входные файлы/node_modules/runtime исключены из Git.

## Решения относительно старого каркаса

- Streamlit заменяется React + Vite + TypeScript по новому выбору участника.
- CRM, заказы, скидки/возвраты и согласование писем не входят в новый процесс.
- На 15 ноября первым кандидатом был Yandex. После FAQ 19 ноября он заменён
  локальным llama.cpp.
- Старые 11 API checks, 13 fixtures и замечания Ruff относятся только к архиву
  и не выдаются за проверки нового backend.
- Корневая .venv сохранена, но содержит пакеты прежнего кейса.
- Имя корневой папки сохранено; Git не переинициализировался, коммитов/remote нет.

## Следующие проверки при реализации

Разбор реальных файлов, корректность locator/цитат, правила версий/доступа,
ограничения локальных chat и embeddings, размеры/лимиты, hybrid retrieval,
generation publish, восстановление и UI. Набор описан в
[EVALUATION.md](../quality/EVALUATION.md).

Для этого подготовительного этапа проверяются только структура и ссылки,
валидность JSON-примеров/manifest, сохранность архива и gitignore.
Без работающего Docker Engine и приложения нельзя заявлять о проверенной сборке.
