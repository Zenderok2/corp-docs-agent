# Проект API и данных

Проект контрактов v1 от 25 ноября 2026. Сверить с ТЗ в день кик-оффа.
Для первого прохода достаточно файлового импорта, вопросов, цитат и health.
В MVP добавить приём заметок о практике. Форма доступна сотруднику,
а очередь открывается только проверяющему. Полноценные роли и история
остаются расширением.

## Общие правила

- Префикс `/api/v1`, JSON UTF-8, ID — непрозрачные строки, даты/время ISO 8601.
- Моменты хранятся в UTC; `as_of` — календарная дата и применимая timezone
  организации. Если дату не указали, сервер фиксирует используемую дату в вопросе.
- Списки имеют limit 1–100, cursor и next_cursor. Неизвестные поля входных схем запрещены.
- Principal и группы получает сервер из доверенного контекста; клиентские
  document_ids/department/legal_entity только сужают область поиска.
- Запуск загрузки, обработки и вопроса использует `Idempotency-Key`.
  Повтор того же тела возвращает тот же ID; иное тело с тем же ключом — 409.
  Для upload учитываются hash файла и значимые метаданные, а не случайная multipart boundary.
- Error: `error.code`, `error.message`, `error.request_id`, безопасные field details.
  Ошибки не содержат ключи, пути storage, traceback и тексты документов.

## API

| Метод и путь | Смысл | Результат |
| --- | --- | --- |
| `GET /health/live` | Процесс жив | 200 без вызова модели |
| `GET /health/ready` | БД, настройки и зависимости выбранного режима готовы | 200/503, Chroma требуется для hybrid, отсутствие готового корпуса видно отдельно |
| `GET /api/v1/capabilities` | Провайдеры, режимы, форматы и ограничения | 200 без секретов; готовность API не подтверждает доступность live модели |
| `GET /api/v1/documents` | Разрешённые документы | Пагинация, фильтры; без раскрытия чужих названий/счётчиков |
| `POST /api/v1/documents` | Создать документ и первую версию | Multipart file + metadata, 202 document/version/job IDs |
| `GET /api/v1/documents/{id}` | Метаданные и доступные версии | 200/404 после scope-check |
| `POST /api/v1/documents/{id}/versions` | Добавить редакцию | 202; не публикует её как действующую автоматически |
| `PUT /api/v1/document-versions/{id}/publication` | Подтвердить статус/область/действие | Администратор, optimistic version check, аудит; 409 при конфликте |
| `POST /api/v1/document-versions/{id}/index-jobs` | Запустить/повторить индексирование | 202, не более одного активного задания на версию/профиль |
| `GET /api/v1/index-jobs/{id}` | Прогресс и предупреждения | queued/running/completed/failed/needs_ocr |
| `GET /api/v1/document-versions/{id}/content` | Оригинал/безопасный просмотр | Проверка доступа при каждом обращении, без file-system paths в API |
| `DELETE /api/v1/document-versions/{id}` | Отозвать/удалить из поиска | Администратор; доступ закрывается до фоновой очистки Chroma |
| `POST /api/v1/questions` | Вопрос и бизнес-контекст | 202 question_id и status=queued |
| `GET /api/v1/questions/{id}` | Состояние и ответ | 200, доступ к записи и всем использованным источникам проверяется заново |
| `POST /api/v1/questions/{id}/follow-ups` | Уточнение предыдущего вопроса | Новый question_id, серверная связь с разрешённой историей |
| `GET /api/v1/citations/{id}` | Точная выдержка и locator | 200/404; недоступная цитата не раскрывает название/фрагмент |
| `POST /api/v1/questions/{id}/feedback` | helpful/not_helpful + комментарий | 201, сохраняется автор и версия ответа |
| `POST /api/v1/questions/{id}/practice-reports` | Сохранить пример по выбранной цитате | 201 с ID и статусом `pending_review` |
| `GET /api/v1/practice-reports` | Очередь команды качества при наличии экрана | 200 только для проверяющего. На первом проходе допустима служебная команда |

Загрузка для MVP запускает сохраняемую фоновую обработку. UI опрашивает job;
завершение HTTP-загрузки не равно ready. Streaming/SSE — последующее расширение.

Пример вопроса:

```json
{
  "question": "Кто должен подписывать агентский договор?",
  "as_of": "2026-11-15",
  "context": {
    "legal_entity": "example_entity",
    "department": "example_department"
  },
  "filters": {
    "document_ids": []
  }
}
```

Пустой document_ids означает все разрешённые документы, не весь корпоративный
корпус. Бизнес-контекст уточняет вопрос, но не доказывает принадлежность к подразделению.

## Смысловой результат ответа

| Поле | Содержание |
| --- | --- |
| question_id, answer_id | Серверные ID |
| job_status | queued/running/completed/failed |
| outcome | answered/partial/needs_clarification/not_found/conflict; только у completed |
| answer | Краткий текст с подтверждёнными пунктами |
| claims | text + citation_ids для проверяемых утверждений |
| citations | Только проверенные сервером ссылки |
| clarification | Один конкретный вопрос, если он нужен |
| missing_information | Что не удалось подтвердить |
| conflicts | Суть противоречия + IDs источников, без выдуманного разрешения |
| as_of, corpus_revision, index_generation_id | Контекст ответа и воспроизводимость |
| trace | Разрешённые инструментальные шаги: тип, IDs, длительность, статус |
| usage | LLM/tool calls, retries, tokens при наличии, latency, provider/profile |

Технический timeout/недоступность локальной модели — `job_status=failed` с error, а не
`not_found`. `partial` разрешён только если хотя бы часть ответа подтверждена,
а остальное явно отделено. При полном отсутствии доказательств нет выдуманного
answer «по общим знаниям». Числовую самооценку LLM не выдавать за вероятность истины.

## Citation и locator

Citation: `id`, `document_id`, `document_version_id`, `chunk_id`, `block_ids`,
`title`, `version_label`, `publication_status`, `effective_from/to`, `quote`,
`locator`, `content_url` через собственный API, `source_hash`.

Locator — типизированный вариант:

- `pdf`: физическая page_number, необязательная page_label и прямоугольники
  фрагмента. Для нескольких страниц перечислить locator каждого блока.
- `docx_paragraph`: section_path, paragraph_index, стабильный block_id.
- `docx_table_cell`: section_path, table_index, row_index, column_index,
  paragraph_index и block_id; вложенные таблицы — явный path.

Публичные номера страниц/абзацев/строк/столбцов — с **1**. Диапазоны текста,
если нужны, задаются полуинтервалом Unicode code points в каноническом тексте
блока; frontend не должен путать их с UTF-16 offsets JavaScript.
Версия нормализации сохраняется. Quote сверяется с конкретной исходной версией;
модель выбирает ID из полученного набора, а не конструирует путь/URL источника.

## Пример применения регламента

Тело POST содержит `answer_id`, `citation_id`, `situation` и `action_taken`.
Поля текста обязательны и ограничены по длине. Backend проверяет принадлежность
ответа вопросу, цитаты ответу и видимость версии документа. Из цитаты берёт
`document_version_id` и координаты пункта. Автор и время назначаются сервером.
Повтор запроса с тем же `Idempotency-Key` не создаёт вторую запись.

Первый статус — `pending_review`. В дальнейшем проверяющий сможет одобрить
или отклонить заметку. Опубликованные примеры при наличии этой функции
отображаются отдельно от цитат. Сам ввод заметки не добавляет данные
в извлечение нормативных доказательств.

## Основные сущности SQLite

| Сущность | Назначение/ограничения |
| --- | --- |
| documents | Семейство, название, владелец, источник, область и corpus_kind (regulations/product_licensing) |
| document_versions | Оригинал/hash, редакция, обработка, подтверждённая публикация, даты, metadata_revision |
| version_relations | supersedes/amends/related_to с областью изменения, без автоматического универсального приоритета |
| document_access | Разрешения/группы и версия ACL; формализуются с заказчиком |
| blocks | Извлечённый текст, locator и parser_version, привязка к неизменяемой версии |
| chunks | Текст поиска/контекста, отображение в blocks, chunker_version |
| chunks_fts | FTS5 представление; привязка к проверенным chunks, синхронизация с публикацией |
| embedding_profiles | Provider + document/query model, размерность и версии/preprocessing |
| index_generations | Building/ready/active/retired/failed, profile и corpus_revision |
| index_jobs | Статус, attempt, error_code, counters и времена; сохраняются при рестарте |
| questions / answers | Principal, контекст, дата, поколения, outcome, результат и политика хранения |
| citations / answer_claims | Проверенные ссылки и связь утверждений с источниками |
| feedback | Оценка сотрудника и комментарий, не истина для автоматического обучения |
| practice_reports | Автор, ответ, цитата, версия пункта, ситуация, действие, статус и время. Связи проверяются при записи |
| audit_events / idempotency_keys | События/права/публикация, атомарные ключи повторов |

Включить foreign_keys, транзакции и миграции. Не держать транзакцию записи
открытой во время PDF-разбора, LLM или обращения к Chroma.

## Метаданные, которые ещё надо согласовать

Юрлица/подразделения и их идентификаторы, даты действия и границы периодов,
обязательная иерархия источников, правила отзыва, делегирование полномочий,
извлечение приказов об изменении отдельных пунктов, политика истории/удаления.
Пока не подтверждены — сохраняются как неизвестные, без автоматического назначения.

## Ошибки

| HTTP/code | Ситуация |
| --- | --- |
| 401/403 unauthorized/forbidden | Не подтверждён principal/нет права операции |
| 404 not_found | Объект не найден в разрешённой области |
| 409 metadata_conflict/idempotency_conflict/job_active | Устаревшая версия или конфликт запроса |
| 413 upload_too_large | Превышен согласованный размер |
| 415 unsupported_format | Формат не поддерживается |
| 422 invalid_metadata/invalid_question/invalid_practice_report | Ошибка входной схемы или несогласованная привязка заметки |
| 429 capacity_exceeded | Превышен бюджет активных задач |
| 503 corpus_not_ready/provider_unavailable/index_unavailable | Нет доступного готового контура |

Ошибки асинхронного задания возвращаются через последующий GET как failed.
При отзыве доступа во время ответа/чтения истории вернуть безопасную ошибку
source_access_changed; не отдавать ранее сгенерированный раскрывающий текст.
