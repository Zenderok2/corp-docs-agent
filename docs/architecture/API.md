# Реализованный API v1

В режиме локальной разработки OpenAPI доступен по `/api/docs`. Все
пользовательские запросы идут на тот же origin через `/api/v1`. Ошибки
возвращают HTTP-статус и короткий код в `detail`.

| Путь | Операция |
| --- | --- |
| `GET /health/live`, `GET /health/ready` | Жизнь процесса и отдельная проверка корпуса, модели, очереди и активного индекса |
| `GET /session`, `POST /session`, `DELETE /session` | Создание демосеанса, вход с кодом участника или службы качества, выход |
| `GET /documents` | Доступные версии документов, фильтрация по роли, пагинация |
| `GET /document-versions/{id}/content` | Постраничная выдача извлечённых блоков в порядке документа |
| `POST /questions`, `GET /questions/{id}` | Создание задания, опрос его состояния и чтение ответа владельцем |
| `GET /questions` | Последний вопрос каждой недавней ветки текущего сеанса |
| `POST /questions/{id}/follow-ups` | Ответ на открытое уточнение, наследование вопроса и контекста |
| `GET /citations/{id}` | Цитата, соседний текст, редакция, координаты и SHA-256 файла |
| `POST /questions/{id}/practice-reports` | Передача примера по выбранной цитате на проверку |
| `GET /quality/cases`, `PUT /quality/cases/{id}` | Очередь пробелов, публикация, закрытие и отзыв ответа |
| `GET /quality/practices`, `PUT /quality/practices/{id}` | Очередь примеров, одобрение и отклонение |

У путей в таблице, кроме health, есть префикс `/api/v1`. Подписанная
cookie хранит идентификатор сеанса и роль. Корпус демосеанса отличается от
рабочего корпуса участника. Служба качества видит обе очереди. Идентификаторы
документов и бизнес-контекст ограничивают выбранный корпус в рамках роли.

## Вопрос и ответ

`POST /questions` принимает `question`, необязательные `as_of` (дата
применимости), `context` и `document_ids`. Поля контекста — `legal_entity`,
`department`, `product` и `license_type`. На создание вопроса и уточнения можно
передать `Idempotency-Key`. Повтор того же тела возвращает ID полученного задания.

Задание проходит `queued → running → completed` или `failed`. Поиск учитывает
редакции, сроки, области и явно заданные связи. Локальная модель выбирает исход
и координаты цитат из ограниченного списка фрагментов. Код сверяет каждую
выдержку с текстом версии в SQLite. Текст ответа строится из проверенных цитат.
Ответ содержит исход, источники, уточнение при необходимости, статистику вызовов
и состояние запроса в службу качества. Изменение корпуса посреди работы прерывает
ответ. При чтении повторно проверяется разрешение на все процитированные версии.

## Служба качества

При исходах «не найден», «частичный ответ» и «конфликт» система регистрирует
обращение по ветке вопроса. Проверяющий указывает проверенный ответ, основной
вопрос, до пяти вариантов формулировки и необязательный срок действия. Повторное
использование учитывает роль, сведения об области, дату и ответы на уточнения.
Достаточный ответ из регламента имеет приоритет. Отзыв сразу убирает публикацию
из повторного использования.

Пример применения связан с идентификаторами цитаты, версии и исходного блока.
Проверенная практика выводится рядом с тем же пунктом. Для поиска нормативных
оснований используется индекс регламентов. Все очереди и история переносят
перезапуск SQLite.
