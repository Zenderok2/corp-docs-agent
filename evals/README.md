# Оценка качества

Отдельный контрольный набор с ответами организатор не выдаёт. После получения
корпуса заполните по карточке на вопрос из каждого набора и для составных случаев.
[План приёмки](../docs/quality/EVALUATION.md).

Для вопроса фиксировать: case_id, question, context, as_of, expected_status,
expected_claims, expected_citations, forbidden_claims и видимость документов.
Держать вопросы для настройки отдельно от контрольных. Синтетические и
реальные разрешённые примеры маркировать раздельно.

Отчёт содержит версии корпуса/индекса/embeddings/модели, задержку, usage,
фактический результат и ручную оценку поддержки утверждений источниками.
Реальные вопросы сотрудников и документы по умолчанию в Git не включать.

## Карточка контрольного вопроса

| Поле | Значение |
| --- | --- |
| ID, набор и вопрос | |
| Дата, продукт/версия, юрлицо | |
| Исход answered / partial / needs_clarification / not_found / conflict | |
| Обязательные тезисы и условия | |
| Для каждого тезиса: файл, редакция, страница/пункт, выдержка | |
| Недопустимые выводы | |
| Найденные основания, проверка ответа, задержка | |

Оценивать отдельно факт нахождения каждого опорного фрагмента и правильность
ответа. Сравнить FTS5 и hybrid на одних контрольных случаях. Для составного
вопроса засчитывать полный ответ, только если найдены и использованы все
необходимые основания. Отказ оценивать по уместности и объяснению.
